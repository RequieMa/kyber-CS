# L3 · 指令与 CPU——程序是一串小指令

```
   L0  框架
   L1  软件
   L2  软件 ↔ OS
 ▶ L3  指令          ◀ 你在这里
   L4  数字逻辑
   L5  比特与物理
```

**从上层带下来的问题：** OS 自己也只是一个程序。那一个运行中的程序*到底*是什么？「运行」是什么意思？

**核心思想。** 一个运行中的程序 = 一串极简的**机器指令**，一颗芯片（**CPU**）一条接一条地执行，每秒数十亿次。每条指令简单到几乎侮辱智商：*把这两个数加起来、把这个数复制到那里、比较它们、跳到列表另一处。* 就这些。一切——甜甜圈、OS、你的浏览器——都是由几百万条这种微小步骤搭起来的。

CPU 用一个简单到有名字的循环来跑它们：**取指—译码—执行循环**（fetch–decode–execute cycle）：

```
          ┌─────────────────────────────────────────────┐
          │                                               │
          ▼                                               │
   ┌─────────────┐   ┌─────────────┐   ┌──────────────┐  │
   │  1. 取指     │──►│ 2. 译码      │──►│ 3. 执行       │──┘
   │  从内存取下  │   │ 这是什么     │   │ 真正做它     │
   │  一条指令    │   │ 命令？       │   │（加、复制、跳）│
   └─────────────┘   └─────────────┘   └──────────────┘
        （……然后重复，每秒数十亿次……）
```

这个循环，是每一台存在过的计算机的「心跳」。

**现在跟住我们那条线。** 在 L1 中，甜甜圈的 `render` 函数用一行旋转数学来转每个点。让我们抓住其中**一行**——就一行——再也不松手：

```python
x = x * cosA - y * sinA      # ← 这条线。我们跟着它一路到底。
```

对你来说，这是一行。对 CPU 来说，这行也太大了——必须拆成好几条指令。这是它在**汇编**里的样子（汇编是 CPU 实际指令的人类可读形式——不用背，只感受*颗粒度*）：

```asm
    mul   r1, x, cosA      ; r1 = x * cosA       （一次乘法）
    mul   r2, y, sinA      ; r2 = y * sinA       （又一次乘法）
    sub   x,  r1, r2       ; x  = r1 - r2        （一次减法）
```

一行数学 → 三条指令。`r1`、`r2` 是**寄存器**——CPU 内部的一小撮格子，存放*此刻*正在处理的数据。CPU 取 `mul`，译码"啊，是乘法"，执行；然后下一条；再下一条。甜甜圈每一帧旋转，CPU 就把这小段三人组跑几千遍。

> **两种语言在这里收敛。** 我们的甜甜圈终端和桌面的后端用 Python 写，浏览器用 JavaScript——两种语言在纸面上看起来差别不小。但那同一行旋转，在*任意*一种语言里，落到 CPU 上都变成同样的 `mul, mul, sub`。高级语言是给*人*看的；底下它塌缩成 CPU 极小的词汇表。沙漏开始收窄：**三张脸甚至两种语言，在这里开始变得一模一样。**

**甜甜圈在这一层。** 甜甜圈流畅的旋转，被揭示为取指—译码—执行循环在每一帧里反复研磨 `mul, mul, sub`（以及它们的几千个同类）。动画*就是*这个循环，变得可见。

**悬念。** CPU 「执行」了 `sub`——它做了减法。但 CPU 是一片硅，没有手指，也不知道数字是什么。**一片硅到底怎么做减法？** → **L4**

> **一句话旁注。** 把你可读的 `x = x*cosA - y*sinA` 变成 `mul/mul/sub` 指令是*编译器*（或者对 Python/JS 来说是*解释器*）的活——怎么做好这件事，本身就是一门深课。*计算理论*也在这一层附近，它问的是一个大问题：任何一串指令，到底能算什么？永远不能算什么？
