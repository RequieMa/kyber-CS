# 收束——再爬回顶端

```
   L0  框架             ▲   "一个甜甜圈"
   L1  软件             │   重塑数据
   L2  软件 ↔ OS        │   通过请求 OS
   L3  指令             │   OS 运行微小指令
   L4  数字逻辑         │   由门搭成
   L5  比特与物理       │   由切换的电压构成
                        └─── 我们一路下降到底，再爬回来
```

让我们逆着同一条线快速跑回去，因为整件事的意义就在于把它感受为**一条连续的链**：

> 一根线上的**电压**（L5）是一个**比特**。几个切换的晶体管搭成一个**门**（L5→L4）。门搭成**加法器**，执行了那次 **`sub`** 指令（L4→L3）。CPU 在它的**取指—译码—执行**循环中，与几百万条其他指令一起跑完这条指令（L3）。其中一些程序有特权，组成了 **OS**；其余是客人，**请求** OS 触碰硬件（L2）。一个这样的客人持有小小的**状态和一个 `render` 规则**——甜甜圈的想法（L1）。把这个想法透过三张**映射表**之一上色，你就得到了终端、桌面或浏览器的**脸**（L0）。

现在退后一步，看整段旅程的形状——**沙漏**：

```
   终端     桌面     浏览器        ← L0–L1：三张脸，一个想法
        \   (字符/色块/圆点)  /          软件发散成无数想法
         \        │            /
          \       │           /        ← L2：三扇门，一个 OS 边界
           \      │          /
            \     │         /          ← L3：脸与语言塌缩——
             \    │        /                 同样的 mul/mul/sub
              \   │       /            ← L4：同样的门
               \  │      /
                \ │     /              ← L5：同一股切换的电压
                 \│    /                     硬件收敛成唯一机制
                  ·  ·
```

这个形状*就是*我们开头那句命题：

> **软件是被抽象出来的想法。硬件是忠实地执行指令的镜子。**

在顶端，软件自由地成为许多东西——三种画风、两种语言、无限种可能的甜甜圈——因为想法没有重量，想要多少有多少。这种自由就是**抽象**：「甜甜圈」是「一个想法」，恰恰是因为我们约好了在上面不去操心它到底怎么被画出来。画风只是一个*参数*——想法上的一个旋钮。

在底端，硬件没有这种自由，也不想要。它只做一件事：维持电压并切换它们，忠实地，完全按指令要求的模式。它分不清甜甜圈和电子表格。这种无心的忠实是它全部的美德——正因如此，上面的想法才能信任它。

计算机科学，从头到底，是在这面忠实的地基上建造**一层又一层的抽象之塔**：门藏起晶体管，指令藏起门，程序藏起指令，OS 藏起硬件，你的想法藏起这一切。每一层都让上一层不必再操心下一层。**这就是整个游戏。** 你要上的每一门课，都是在精读这座塔的某一层楼。

你进来时看到三个毫不相像的窗口。你现在确切知道它们共享什么：**一切，从想法一路到电压——它们不同之处仅在于最顶端的一行画风配置。**

这就是全貌。欢迎。
