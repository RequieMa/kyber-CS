# L1 · 软件——一切都是数据 + 规则

```
   L0  框架
 ▶ L1  软件          ◀ 你在这里
   L2  软件 ↔ OS
   L3  指令
   L4  数字逻辑
   L5  比特与物理
```

**从上层带下来的问题：** 三张脸看起来毫不相像，却同步旋转。它们共享了什么？

**核心思想。** 这是第一个重大揭示，而且它适用于*每个*程序——你的浏览器、一个视频游戏、银行的工资系统、甜甜圈：

> **所有软件做的事，本质上都是：保存一些数据，再按规则把它重新塑形。**

就这样。浏览器保存网页数据，把它重新塑形成像素。游戏保存世界数据，把它重构成下一帧。甜甜圈保存一丁点数据，把它重构成一幅画。

甜甜圈保存了什么数据？几乎没有——只有几个数字：

```python
# 甜甜圈的整个"状态"——程序需要记住的一切
state = {
    "A": 1.0,   # 绕一个轴转了多少
    "B": 1.0,   # 绕另一个轴转了多少
    "pos": 50,  # 甜甜圈在我们共享世界里的位置（0–100）
}
```

而「规则」是一个函数，把状态变成一幅画。不是变成*屏幕上的光*——只是变成一格格的亮度数字，纯数据进，纯数据出。

输出是一格格数字，像 `[[0, 0, 3, 7, 9, 7, 3, 0], …]`。**只是亮度，不是像素。** 只是数据。

**三张脸从哪来？** 这是整份文档的心脏。亮度网格对三者完全一致。每张脸的区别只在于如何把亮度数字变成可见的东西——一张小小的查找表，叫做 *ramp*（映射表）：

```python
TERMINAL_RAMP = " .:-=+*#%@$"          # 亮度 0..10 → 一个字符
DESKTOP_RAMP  = " ░░▒▒▓▓██"            # 亮度 0..10 → 一个色块
BROWSER_RAMP  = [从暗到亮的彩色圆点]    # 亮度 0..10 → 一个彩色点
```

这就是 L0 那团谜的答案。三张脸共享**整套想法**——状态和 `render` 规则。它们的不同只在于一个**参数**：用哪张映射表上色。改一行配置，终端就能画得跟浏览器一样。想法是一件东西，外观只是一个旋钮。

> 这就是活生生的*抽象*：「甜甜圈」是单一的想法，不在乎自己是用字符、色块还是圆点画的。

**甜甜圈在这一层。** 我们已经看到了甜甜圈作为软件的全貌：一点状态、一个 `render` 规则、一张可更换的画风映射表。我们会**冻结这个版本**，以后不再重新解释——从这里往下，我们只追着它里面*一根线*。

**悬念。** 再看一眼 `render`。它算出了一格格数字，然后……停了。它从未让屏幕发光。程序可以算出一堆亮度数字，但亮度活在程序自己的内存里。**程序里面的数字，到底怎么变成物理屏幕上的光？** 原来，程序*自己做不到*。→ **L2**

> **一句话旁注。** *怎么*存状态——这里是小小的字典，但也可以是列表、树、数据库——正是*数据结构与算法*这门课的主题。它问的是：给定程序要做的事，怎样存放数据最聪明？
