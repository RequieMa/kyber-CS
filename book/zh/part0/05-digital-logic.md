# L4 · 数字逻辑——指令由逻辑门搭成

```
   L0  框架
   L1  软件
   L2  软件 ↔ OS
   L3  指令
 ▶ L4  数字逻辑      ◀ 你在这里
   L5  比特与物理
```

**从上层带下来的问题：** CPU 「执行」了 `sub`——一片硅到底怎么做减法？

**核心思想。** CPU 里的数字用**二进制**（0 和 1 的字符串）写成。对它们的运算，则由几个极其简单的决策器——**逻辑门**——搭建而成。每个门接收一或两个 1/0 输入，产生一个 1/0 输出，遵循一条固定规则。门的种类只有这么几种：

```
   AND  → 两边都是 1 才输出 1              OR   → 任意一边是 1 就输出 1
   XOR  → 两边不同才输出 1                 NOT  → 翻转：0→1, 1→0
```

就这些。整个工具箱。从*只有这几样*，你可以搭出算术。往下看。

**跟住我们那条线：** CPU 的 `sub`（和它的兄弟 `add`）由一个叫**全加器**的小电路搭成——一个把两个二进制位加"来自上一列的进位"加起来的装置，跟你手算加法、进位 1 的方式一模一样。一列长这样：

```
        a ──┐
            ├──[ XOR ]──────────────► 和   （你写下来的那位）
        b ──┘        └──[ XOR ]─► 跟进位输入一起
                                                       ┌─[ AND ]─┐
        a ──[ AND ]── b  ───────────────────────────►─┤  OR     ├─► 进位输出
        进位输入 ─[ AND ]─ (a XOR b) ─────────────►──┘         │   （你进上去的 1）
                                                       └─────────┘
```

**`sum` 只是一次 XOR，`carry` 只是一些 AND 加一次 OR。** 加法就是门。减法就是加法，把其中一个数翻转（一次 NOT 加一个技巧）。给两个 32 位的数相加？把 32 个全加器串成一排，每个把进位传给下一个——一次**行波**——你就搭出了 CPU 里执行 `sub` 的那个部件。

那种稳定的节奏——取指、译码、执行、取指、译码、执行——又是从哪来的？**时钟**：一次每秒数十亿次的电脉冲。每一拍，门的结果稳定下来，**寄存器**（由能*保持*值的门搭成）锁住结果，准备好给下一拍用。甜甜圈的整个旋转动画，就是由这个节拍拍出来的。

**甜甜圈在这一层。** 我们那条线上的那次减法——`sub x, r1, r2`——现在完全被解开了：它是一排由 XOR/AND/OR 门搭成的全加器，随时钟节拍锁存答案。甜甜圈在转，是因为几百万个这种门在每一拍、每一帧里同步翻转。

> **沙漏最窄处。** 这个深度没有「终端的甜甜圈」或「浏览器的甜甜圈」，也没有 Python 或 JavaScript 之分。只有一个减法，由同一批门搭成，无论你从哪张脸看过去都一模一样。画风在顶端发散；在这里，一切都收敛成唯一的机制。

**悬念。** 门输出 1 或 0。我们从头到尾一直把 "1" 和 "0" 写得好像它们不言自明。但芯片是物理物体。**「1」到底是什么？门又是由什么做的？** → **L5**

> **一句话旁注。** 设计这些电路，让它们又快又小又正确，是*数字设计与计算机体系结构*——你会亲手用门搭出一颗能跑的 CPU 的课程。它不像听起来那么像魔法，而且成就感远胜于想象。
