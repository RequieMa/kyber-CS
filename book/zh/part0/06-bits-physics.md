# L5 · 比特与物理——1 是电压，门是开关

```
   L0  框架
   L1  软件
   L2  软件 ↔ OS
   L3  指令
   L4  数字逻辑
 ▶ L5  比特与物理    ◀ 你在这里（地板）
```

**从上层带下来的问题：**「1」到底是什么，物理上？门又是由什么做的？

**核心思想——以及地板。** 到底了。门之下不再有计算机科学，只剩物理。而答案朴素到近乎滑稽：

> **1 是高电压。0 是低电压。** 一个比特不过如此——某根线此刻是电学上的"高"还是"低"。

门呢？门由**晶体管**搭成，而一个晶体管不过是一个由电控制的微型**开关**：

```
        晶体管 = 一个由电操作的开关

            控制端（"栅极"）
                  │
                  ▼
        入 ───────●───────► 出
                  │
        控制端为高（"1"）：开关闭合 → 电流流过 → 输出为 1
        控制端为低（"0"）：开关断开 → 无电流   → 输出为 0
```

这就是整个地基。把几个开关接在一起，让电流只有在*两个*控制端都为高时才能通过——你就搭出了一个 AND 门。再多几个开关做成 OR、NOT、XOR。门堆成加法器（L4）。加法器堆成 CPU（L3）。CPU 运行指令（L3）。把有特权的指令包成 OS（L2）。程序向 OS 请求（L2）。程序重新塑形数据（L1）。而它重塑的数据，可以是一个旋转的甜甜圈（L0）。

**甜甜圈在这一层。** 我们那条线追到了它的终点。那次减法结果的一个位——`sub x, r1, r2` 之后 `x` 的最高位——此刻就是芯片内一根线上的**一个电压**，由几个正在切换的晶体管维持高或低。乘以几百万个位，结果就是一格格亮度数字。这网格变成一次向 OS 的请求，OS 设置驱动你屏幕像素（或构成字符形状的圆点）的电压，这些像素发出**光子**——真正的光——落入你眼中，成为旋转的甜甜圈。

```
   一个晶体管在切换
         │
         ▼  （几个晶体管）
   一个逻辑门                  ← L5/L4 边界：物理变成逻辑
         │
         ▼  （串起来）
   一个加法器 → 那次 `sub`     ← L4/L3
         │
         ▼  （几百万个，随时钟节拍）
   CPU 在跑指令                 ← L3
         │
         ▼  （许多程序中的一个特权程序）
   OS 在响应请求                ← L2
         │
         ▼  （一个客人程序在请求）
   你的程序在重塑数据            ← L1
         │
         ▼
   一个甜甜圈，在旋转，在光里     ← L0
```

物理不懂甜甜圈。它只维持电压，忠实地，完全按指令要求的模式。意义——「这是甜甜圈」——完全活在那些上层。**硬件是一面无心的、完美的镜子。**

我们踩到了地板。现在爬回去，看看我们搭了什么。
